## 2. 指标协议

官方 ESCounts 代码口径：剔除 0 计数视频（test 151/val 130），MAE = |round(p)−g|/(g+0.1)，
OBO = |round(p)−g|≤1。用该口径复现 ESCounts 官方权重：test **0.2151 / 0.5563**（论文 0.213 / 0.563）。
全视频口径作为补充。选模只用 valid（或 UCFRep dev），test 每个模型只评一次。

## 3. 开发轮次（RepCount-A valid，MAE_p，均值±SD）

| 变体 | n | MAE_p |
|---|---|---|
| v1 TempoRAC：速率专家 + tempogram 软路由（特征级/密度级/竞争式 MoE/仅 tempogram/平滑） | 1–3 | 0.212–0.240（均不优于拼接） |
| 路由机制分析 | – | 路由学成与节奏无关的常数混合（各周期区间约 [0.02,0.44,0.53]） |
| single_r4 | 5 | ≈0.212 |
| concat {1,2,4} | 3 | 0.214 |
| concat {2,4,8}（多速率金字塔） | 3 | **0.204±0.001** |
| + tempogram 注意力偏置 | 3 | 0.198±0.008 |
| + 节奏扭曲训练 | 3 | 0.199±0.008 |
| + 偏置 + 扭曲 | 3 | 0.199±0.015 |

结论：按"去掉组件不掉分就重设计"的要求，v1 的软路由不成立（保留为负结果）。

误差形态：过计数为主——预测/真值比 1.15–2.4 的视频贡献约一半误差（倍频：俯卧撑 6→14、
前平举 4→8）。这与 11-05 协议中 Astra 提出、需证据支持才启用的 (C) "节奏约束事件解码"一致，
因此 v2 对齐分支的 A/B/C：

- (A) 局部掩码 tempogram（节奏与可靠度证据），作为注意力偏置；
- (B) 多速率事件证据金字塔 {2,4,8}；
- (C) 节奏一致性解码：由密度推候选周期 q，读取 tempogram 在 q/2、q、2q、3q 的证据，学习有界
  [1/2, 2] 的逐格校正（初始化为恒等），抑制倍频/半频；仍只有两项损失。

## 4. 已修正的问题（原始记录保留在服务器 `runs/_*` 归档目录）

- 启动器重复启动同名任务 → 归档污染日志，启动器改为跳过存活/部分完成任务。
- 容器内存上限 133 GB（非宿主机 503 GB）导致进程被杀 → 4×4 特征副本、降低预取、队列并发。
- 扭曲训练对裁剪窗外周期用 `np.interp` 钳位，导致窗外周期整块挤入边缘 → 改为线性外推；
  CPU 校验：扭曲前后目标质量平均差 0.004。
