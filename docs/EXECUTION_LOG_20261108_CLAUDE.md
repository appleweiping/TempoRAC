## 2. 指标协议

官方 ESCounts 代码口径：剔除 0 计数视频（test 151/val 130），MAE = |round(p)−g|/(g+0.1)，
OBO = |round(p)−g|≤1。用该口径复现 ESCounts 官方权重：test **0.2151 / 0.5563**（论文 0.213 / 0.563）。
全视频口径作为补充。选模只用 valid（或 UCFRep dev），test 每个模型只评一次。

### 3h. 引入 LLM（11-09 用户决定："用 LLM，即使方法性质、算力需求和论文主线都会大变"）

设计：冻结 Qwen3-VL-8B-Instruct（SHA-256 逐片核对）读取计数区间内均匀 64 帧 + 计数指令，缓存指令末/回答末隐状态与
逐 2 帧组的语义 token（`mllm_features.py`）；计数头以 FiLM（全局）与时间对齐语义流（按帧号放入金字塔网格）条件化，
计数仍由密度积分完成。冒烟：Qwen3-VL 对"一次完整重复"的描述准确，零样本计数不可靠（7/4、9/10、9/7）。
修正：`video_metadata` 必须放入 `videos_kwargs`，否则时间戳按 24 fps 连续帧计算（10 s 视频被当作 2.7 s）。
事故：Qwen3-VL 推理占 21.5 GB/卡，与训练进程同卡导致 OOM（GPU0 的 RepCount/QUVA/Countix 分片 0 提取失败、
up12 首个 run 失败并归档于 `runs/_failed_oom_up12_20261109`）→ 改为 GPU0 专跑提取、GPU1 专跑训练。

LLM 条件（冻结 Qwen3-VL，单数据集，5 seed）：UCFRep dev 基线 0.191 → FiLM **0.169** / 语义流 0.186 / 两者 0.180；

**证据（仅验证集，不训练）**：两视图按节奏互补（3l）。只知道动作类别的门控（同类其他验证视频留一估计 2 倍速视图更好的

**新设计**：解码器在金字塔的精确节奏视角上计数（0.5×：金字塔下移一级，需 r1 流，奇数帧不被读取故无插值；1×；2×）；

以字母作答，K 个字母的 softmax 为视角权重，计数 = Σ w_k c_k（仍是密度积分）；损失为混合计数的协议误差

进行中：`runs/oof5`（GPU0，5 折并发）；r1 适配特征提取（`logs/chain_r1.sh`，GPU0，≤5 GB，原子写 meta）；
`views_chain.sh` 待两者完成后生成折外与验证集三视角预测。

**结果（11-11 07:00–08:00，仅训练/验证数据）**：
- 折外（OOF）训练的选择器迁移差：描述 kNN（OOF 记忆）RC +0.1%、CX −0.2%、UCF −10.6%；MLP 更差；OOF 训练的 LLM

  慢节奏验证片段的多数远更严重；按动作类别的门控 OOF→验证 相关仅 0.39–0.42（UCF ≈0）。OOF 是有偏的训练来源。
- 改为 blending：选择器只从解码器对验证视频的预测学习，所有验证数字为按源视频分组的 5 折交叉验证（UCF101 组、
  YouTube id 不跨折），轮数由交叉验证选，测试时用在全部验证视频上重训的选择器；测试集只用一次。
  描述 kNN（仅验证记忆，CV）：RC 0.1752→0.1696（−3.2%）、CX 0.2545→0.2442（−4.0%）、UCF 0.1342→0.1265（−5.7%）。
- 精确 0.5× 视角（金字塔下移，r1 全部 9568 视频提取完成）：单独验证 MAE 0.263/0.415/0.211（1×：0.184/0.287/0.128），
  仅在 Countix 周期 <0.4 s 的片段上最好；作为第三候选使 kNN 选择变差（−4.3% → −0.7%）→ 不采用（解码器未见过慢放
  训练样本；写入分析章节）。取消三视角 LLM 运行。
- LLM 选择器（2 视角、描述、仅验证、5 折 CV，每视频每轮 1 个 seed）：CV 第 1 轮 −1.0%（RC −1.3%、CX −2.5%、UCF +0.7%），
  其后过拟合（UCF 最多 +7.6%）→ 不及描述 kNN（−4.3%）。描述 kNN 12 个设置中 11 个为负（中位约 −2.3%，所选最好
  −4.3% 含选择乐观），Countix 12/12、RC 9/12、UCF 10/12 改善 → 稳定但温和。
- 节奏先验（让语言预测周期时长，再选隐含周期最接近者；以训练视频真实周期监督，与解码器无关）：即使用类别中位周期
  （用标签的参照）也无效（RC +0.3% 至 +6%），动作决定的周期误差约 ×1.36，不足以区分相差 ×1.4–2 的两个视角 →
  有效信号不是"节奏本身"，而是"解码器对某类动作哪个视角更可靠"，只能从留出预测中学 → 不采用（`tempo_prior_check.py`）。
- 停止无描述 LLM 版本（仅当 LLM 胜出才需要）。**事先登记的一次有界重试**：针对两个诊断出的弱点——数据少（每视频
  用全部 5 个 seed 的行，5 倍数据并平均标签噪声）与不知基准（kNN 隐式按基准聚类；提示中写明基准，与解码器的
  数据集 token 一致；QUVA 用 RepCount-A）。决策：CV 平均相对变化更优者胜出，持平取更简单的描述 kNN。

  0.0%/−1.3%/−3.5%（−1.6%）；每基准一个先验 +0.9%/−0.6%/−4.6%（−1.4%）→ 起作用的是描述（语言），不是视觉相似或基准。
