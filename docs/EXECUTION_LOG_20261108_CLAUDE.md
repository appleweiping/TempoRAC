## 2. 指标协议

官方 ESCounts 代码口径：剔除 0 计数视频（test 151/val 130），MAE = |round(p)−g|/(g+0.1)，
OBO = |round(p)−g|≤1。用该口径复现 ESCounts 官方权重：test **0.2151 / 0.5563**（论文 0.213 / 0.563）。
全视频口径作为补充。选模只用 valid（或 UCFRep dev），test 每个模型只评一次。

### 3h. 引入 LLM（11-09 用户决定："用 LLM，即使方法性质、算力需求和论文主线都会大变"）

设计：冻结 Qwen3-VL-8B-Instruct（SHA-256 逐片核对）读取计数区间内均匀 64 帧 + 计数指令，缓存指令末/回答末隐状态与
逐 2 帧组的语义 token（`mllm_features.py`）；计数头以 FiLM（全局）与时间对齐语义流（按帧号放入金字塔网格）条件化，
计数仍由密度积分完成。冒烟：Qwen3-VL 对"一次完整重复"的描述准确，零样本计数不可靠（7/4、9/10、9/7）。
修正：`video_metadata` 必须放入 `videos_kwargs`，否则时间戳按 24 fps 连续帧计算（10 s 视频被当作 2.7 s）。
事故：Qwen3-VL 推理占 21.5 GB/卡，与训练进程同卡导致 OOM（GPU0 的 RepCount/QUVA/Countix 分片 0 提取失败、
up12 首个 run 失败并归档于 `runs/_failed_oom_up12_20261109`）→ 改为 GPU0 专跑提取、GPU1 专跑训练。

LLM 条件（冻结 Qwen3-VL，单数据集，5 seed）：UCFRep dev 基线 0.191 → FiLM **0.169** / 语义流 0.186 / 两者 0.180；
多深度 b8+b12 0.164 → +两者 0.170（无叠加收益）。RepCount valid 0.181/0.62 → FiLM **0.177/0.67** / 语义流 0.181 /
两者 0.179。结论：全局 FiLM 有效，时间对齐语义流无效（舍弃）。
